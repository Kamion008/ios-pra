The patch (evidence 1) makes these claims:

K1: strat's mutex hold is now per sector/chunk — the lock/unlock moved
    INSIDE the request loop and the error break stays OUTSIDE the locked
    section (no path exits the loop holding the lock; buf_unmap stays
    outside).
K2: the shared pra_emmc_bounce / pra_emmc_multi_buf copies remain inside
    the same critical section as the IO that fills them.
K3: pra_log_write_sector returns EWOULDBLOCK on try_lock failure (counted
    in pra_log_lock_busy) and counts card-side failures separately
    (pra_log_card_busy); the flusher's complaint line carries both
    counters. The caller's error handling is unchanged (EWOULDBLOCK is
    treated exactly like the old EBUSY: keep position, retry next tick).
K4: at 6 consecutive flusher failures the mutex state is printed once per
    starvation episode (write_fails==6): opaque[1] low-32 = the data word
    (the same layout the panic path's zeroing relies on),
    opaque[0] low-24 = turnstile id, owner decoded via
    ctid_get_thread_unsafe (extern at osfmk/kern/thread.h:1643).
K5: pra_log_flush_tail_locked (new) is the block-copy loop WITHOUT the
    header write; pra_log_flush_locked = tail helper + header (the panic
    path's behavior is unchanged); strat's evidence flush now calls the
    tail helper, so "header total = fully-flushed boundary" holds.
K6: strat flushes the tail every 128 requests (pra_emmc_req_count) from
    INSIDE its locked section — the documented pra_log_strat_flush
    contract ("called with pra_emmc_lock held") is honored — using
    force=true so the unverified-constant time limiter at :1408 is
    bypassed; the request count IS the limiter.

    clock_get_calendar_microtime; the per-thread line and every CI-asserted

K8: CI marker asserts added in the same patch: 'PRA LOG: lock state data=',
    '(lock=%llu card=%llu)', 'cal=%llu.%06llu'.
K9: behavior neutrality: with no new boot args the deltas are (a) lock

## ADDENDUM — patch review round 1 (work/pkt-184450: 0 refuted / 7 weak /
## 3 survive); outcomes adopted

- K1 REVISED (valid catch): the per-iteration critical section ends with
  the count-limited tail flush, so the hold is "one sector/chunk PLUS,
  every 128th request, one 128-block tail flush". Bounded because
  flush_tail_locked STOPS AT THE FIRST failed block (the base's loop exits
  on error), so on a wedged card the flush adds one failed block, not 128.
  The claim's "every hold bounded to one sector/chunk" was overstated.
  Placement stays INSIDE the lock: the contract is real (write_raw drives
  the shared SDHCI channel; the flusher takes the same lock for its own
  writes).
- K2 VERIFIED by construction: the multi-path IO + memcpy sit wholly inside
  one iteration's critical section (the generator only moved the
  lock/unlock lines; the body was not restructured).
- K3 VERIFIED semantics-safe: `grep "== EBUSY" bsd/dev/pra_sdhci.c` over the
  CI buildtree = zero hits; the caller treats any error identically.
- K4 REVISED: the dump condition is now `write_fails == 5` (fires on the
  6th consecutive failure, matching the intent). The two opaque reads
  remain non-atomic (advisory sample, ~ns apart - accepted). The dump runs
  in the FLUSHER's failure path - deliberately NOT under the lock - which
  is exactly what makes it fire during a stuck-hold wedge (and reach the
  screen via the console).
- K5 VERIFIED no -Wunused break: the wrapper still uses `sector` for the
  header write.
- K7 FIXED (real build breaker): clock_get_calendar_microtime takes
  clock_sec_t*/clock_usec_t* and clock_usec_t is 32-bit (clock.h:51-57) -
  the locals now use the prototype's own types with printf casts.
  The deleted SMP-mh format string has no CI assert (verified against the
  assert list).
- K9 REVISED: the behavior-delta list adds (d) the write_sector return-code
  change (EBUSY 16 -> EWOULDBLOCK 35, semantics-safe per K3) and (e)
  force=true refreshing pra_log_strat_flush_at (delays subsequent
  chunk-failure flushes by the limiter window - noted, not fixed).
- H1 REVISED: the review tallies are now attributed per packet.
