T20 = 0196, THE SYNTHETIC UNLOCK SWIPE
Patch: xnu/patches/0196-pra-touch-swipe.patch (142-line diff, SweetHID.cpp
only, +84/-0, 4 hunks). Boot arg `pratouchswipe=N` arms an

eight moves 150 px apart every 20 ms, release at (540,714). That is 10
touch() calls, 180 ms, 1200 px. Normalized into the presented 1125x2436
display (python3 anchor from claim-0196):
```
$ python3 -c 'print(540*1125/1080, 1914*2436/1920, 714*2436/1920)'
562.5 2428.3875 905.925
```
so x 562.5 (centre), down y 2428/2436 (8 px above the bottom, the home
indicator band), release y 906/2436 (mid screen).
It calls touch(), the same function pra_touch's finger path uses, so the
0194 clamp and the edge latch apply unchanged. The latch is set only on
the `!was && down` transition, so the edge bit
(kIOHIDDigitizerEventFromEdgeTip) is on every finger child and the
collection for the whole contact.
There is no start()-time "armed" line: start() runs before the pralog ring
exists (ring61 has 0 panel/surface lines). The first swipe line carries the
interval. The arming block is SILENT on failure, so no swipe line at all is
ambiguous between an unparsed/zero arg, an addEventSource failure, and a
