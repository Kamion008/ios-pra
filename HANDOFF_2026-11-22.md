T21 IMPLEMENTATION FACTS (source-read 2026-11-22; claim-0197 K11/K12)
Recorded so the next session does not re-derive them.
- THE KEY PATH IS UNGATED. `SweetHIDButtons::key(UInt32 usage, bool down)`
  builds `IOHIDEvent::keyboardEvent(mach_absolute_time(),
  kHIDPage_Consumer, usage, down)` and calls `dispatchEvent(event)`; it has
  no finger-slot array, no press latch and no PMIC/SPMI/key-driver
  dependency. The registered instance is reachable as `gSweetButtons`, and
  the existing C wrapper `sweet_hid_key()` already maps index 0 to
  `kHIDUsage_Csmr_Power` (0x30), 1/2 to volume up/down, 3 to Menu.
  Its only caller today is the A5XELTE/SWEET key driver, which is off by
  default on PRA (`A5_KEYS_DEFAULT 0`, 0127) - hence the timer.
- EXPECTED RING SIGNATURE: `SWEET HID: key 0x30 down (1 clients)` and
  `SWEET HID: key 0x30 up (1 clients)` (the log inside key()), plus
  `SWEET HID: event size=60` from dispatchEvent. A down+up pair consumes
  128 B of the 16,384 B queue (60 B event + 4 B entry header = 64 per
  entry). A press fired BEFORE `SWEET HID: queue mapped by SweetHIDButtons`
  is dropped silently but still logs `(0 clients)` - use that count as the
  arming health check.
- THE SAMPLER NEEDS NO PATCH. `sweet_sample.c` takes a COMMA-SEPARATED LIST
  and its fallback default is already "SpringBoard,backboardd"; the PRA
  cmdline overrides it with `sweetsample=Setup`, and Setup never runs, which
  is exactly why no ring has ever had an `SMP <name>[pid]` line. Drop the
  arg (or set it explicitly) and the target list becomes SpringBoard +
  backboardd. Match is exact, case-sensitive `p_comm` equality truncated to
  16 chars (both names fit; longer XPC basenames can never match). First
  sample 90 s after start, then every 120 s, 90 samples max.
- QUEUE ACCOUNTING CLOSED: the 236 B event vs 240 B head stride is the 4 B
  per-entry header (`DATA_QUEUE_ENTRY_HEADER_SIZE` =
  `sizeof(IODataQueueEntry) - 4` = 4, IODataQueueShared.h:79). Not a
  discrepancy, and not something T21 needs to investigate.
